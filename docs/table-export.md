# Client export serialization

## Server export ownership

`createServerExport(schema, onExport?)` owns one export operation at a time. Without an adapter, `available` is false and requests return `unavailable`; the UI must hide the affordance. An adapter receives an immutable request containing format, complete table state, selection, and a separate AbortSignal. It returns an app-owned artifact, not an automatic download. The controller never fetches table pages to assemble a file.

Selection null means the complete matching view; explicit empty IDs mean zero rows. The app must apply the full captured query, including global search, plus the selection constraints and its own authorization checks. Pagination is captured for context, not an instruction to export only that page. Do not silently discard search criteria when executing an inverted selection.

Duplicate pending requests return `busy`. Failures retain the previous accepted artifact and expose the failed captured request for retry. `clear()` removes accepted/requested state and aborts pending work; a monotonic token discards late results even when the adapter ignores abort. `dispose()` additionally prevents reuse. Clear immediately at account or permission boundaries. The snapshot is pull-based; reactive consumers must publish it at request start and completion.

Artifacts and their resources remain app-owned. Offer only accepted artifacts, label retained artifacts with their captured criteria, and manage URL revocation or remote export retention separately. Cancellation prevents publication, not server-side execution or arbitrary callback side effects. Five real HTTP tests cover adapter availability, duplicate submission, snapshot capture, failure/retry, ignored aborts, and invalid input.

The Loupe server-export fixture hides the action without an adapter and uses a real delayed endpoint with a captured serialized table state. Six Chromium executions prove deterministic hydration with zero initial requests, one-operation guarding, whole-view CSV despite page size one, retained anchor identity and accepted criteria through failure, captured retry, exact downloaded CSV/JSON, cancellation, and successful restart. Generic DataTable integration, cross-engine downloads, arbitrary remote artifact types, large-file behavior, and route-unmount URL cleanup remain unqualified.

`createClientExport(rows, columns)` snapshots primitive values from the supplied rows and visible export columns. Each column provides a unique nonempty id, string header, optional visibility, and an accessor returning string, finite number, boolean, or null. Hidden accessors are never evaluated. Objects, Date, undefined, nonfinite numbers, and other unsupported values require explicit app formatting rather than implicit coercion. Accessor failures propagate before any downloadable output is returned.

The returned object exposes rowCount, frozen columnIds, toCSV(), and toJSON(). Both output formats retain supplied row/column order. Later changes to source rows or column definitions do not affect the snapshot. CSV quotes every field, doubles embedded quotes, and uses CRLF record boundaries, following [RFC 4180](https://www.rfc-editor.org/info/rfc4180/). No UTF-8 BOM is inserted. Null and empty strings both render as empty CSV fields; JSON preserves their distinct types and uses column IDs as keys.

CSV string cells and headers that begin with formula markers, leading whitespace/control/format characters before a marker, or initial control/format characters receive an apostrophe prefix inside the quoted field. ASCII and full-width =/+/−/@ counterparts are checked. Actual finite numeric negatives remain numbers rather than being treated as user-provided formula strings. JSON does not receive this CSV-specific mutation.

This is defense in depth, not a guarantee across every spreadsheet program or a subsequent save/reopen cycle. [OWASP describes formula injection and spreadsheet-specific limitations](https://owasp.org/www-community/attacks/CSV_Injection). Ordinary CSV quoting alone does not prevent formulas. Preserve raw values through JSON when exact interchange matters; do not strip the protective prefix before opening untrusted CSV in a spreadsheet. Actual Excel/LibreOffice interoperability remains unqualified.

The caller supplies the complete filtered/sorted client view, reduced to the intended selection, not merely the current page. Column order/visibility must come from accepted table state. This serializer does not decide selection semantics, trigger a browser download, or fetch server pages. Server mode requires the app's onExport callback and must hide export without it. These lifecycle/UI integrations remain unfinished.

`selectClientRows(view, payload, { locale, filterColumns, getRowId, getValue })` resolves the selection before serialization. Explicit IDs intersect the complete current view, retaining its order rather than click order. Missing/deleted IDs are omitted without fetching them. Query selections re-evaluate their captured filter and exclusions, never adding rows outside the supplied view. All visited row IDs must be unique nonempty strings. Passing an empty explicit selection means zero rows, not export-all; a separate export-all action can pass the complete view directly to the serializer.

Five focused resolver tests cover order/identity, query criteria, exclusions, cross-page export, hidden columns, invalid IDs/filters, and missing IDs. The real selection fixture now prepares CSV and checks exact output for explicit cross-page IDs and inverted exclusions. This is serialized-output evidence, not browser download or spreadsheet interoperability evidence.

The fixture now additionally prepares Blob-backed CSV/JSON download links through sheen Link. It keeps the prepared snapshot independent of subsequent selection changes, revokes a replaced URL, and registers disposal cleanup. Three Chromium cases pass twice. The download case reads the actual downloaded files, verifies CSV bytes/CRLF, JSON rows and filenames, excludes hidden fields, checks that later selection changes do not mutate an already prepared file, and confirms a replaced Blob URL is no longer fetchable. URL lifecycle follows the [File API](https://www.w3.org/TR/FileAPI/). Disposal code exists, but the current browser case specifically proves replacement revocation, not route-unmount cleanup.

This is local Chromium download evidence from the Loupe development server. Generic DataTable export affordances, cross-engine downloads, large-file memory behavior, and spreadsheet interoperability remain unqualified.

Six focused tests cover CSV quoting/Unicode, formula-looking strings and headers, numeric negatives, snapshot isolation, hidden-column exclusion, JSON scalar/property safety, invalid values, errors, and empty views. Isolated built-package consumers exercise the client serializer and server-controller availability. The grouped export TODO remains open for generic DataTable state/selection integration and its component API.

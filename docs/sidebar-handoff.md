# Responsive sidebar handoff qualification

The phone drawer retains sidebar application state while modal chrome mounts and unmounts. The `/sidebar-handoff` Loupe route is the isolated qualification fixture for the approach integrated into AppShell; the production integration has its own shell-drawer suites.

The selected approach resolves sidebar content once under its persistent Solid owner, outside a responsive Show. Desktop renders those resolved nodes in an aside. Phone renders the same nodes as children of a normally mounted Dialog. Closing the dialog detaches the nodes without disposing their original owner; reopening or returning to desktop reinserts them. The fixture uses the actual Input and Select implementations, not mocks.

One native Chromium test passes through desktop editing, a phone breakpoint, drawer opening, nested Select opening and Escape restoration, drawer close/reopen, Tab wrapping, and return to desktop. The input retains its DOM marker and uncontrolled value. Background editing works again after modal removal. Lint and root/Loupe typechecks pass. The first test sent a second Escape before the nested Select finished returning focus; it now waits for that observable lifecycle boundary, not a fixed delay.

Do not substitute forceMount without addressing its lifecycle. Inspection of the installed patched Kobalte 0.13.13 DialogContent shows scroll prevention enabled by contentPresent and focus-scope mount/unmount callbacks tied to the retained content ref. Keeping content present is not equivalent to reopening a normal modal. The current approach retains only the application content owner while letting Dialog own its normal layer/focus lifecycle. See [Kobalte Dialog](https://kobalte.dev/docs/core/components/dialog/) and [Solid Portal](https://docs.solidjs.com/reference/components/portal) for the upstream contracts; the installed source and native fixture are the qualification evidence for these pinned versions.

The initial AppShell integration now keeps the owner inside shell contexts, separates desktop and phone visibility, hides desktop navigation on the first phone paint, provides a linked responsive toggle, and recovers focus at breakpoints. Still required for complete qualification:

- Expand route-restoration qualification to other engines and investigate the recorded intermittent main-pane failure. Sidebar-owned unsaved-change and delayed route-restoration registrations now have native coverage described below.
- Expand asynchronous persistence qualification to other engines; pending, rejected, retried, delayed desktop completion, and client disposal now have native coverage.
- Expand visual theme/density/state coverage, nested scoped portals, and background isolation checks. Native scroll/motion checks and the initial reviewed LTR/RTL screenshots are described below.
- Qualify resize with nested overlays open, delayed hydration, accepted/rejected controlled proposals, scroll/draft retention, and all supported test engines.

The implementation task is complete with the later production integration, navigation, visual, controlled-state, overlay, hydration, and scroll-handoff evidence below. Cross-engine and exhaustive release qualification remain milestone-gate work.

Two reviewed 375×750 Chromium screenshot baselines cover obsidian/dark/LTR and paper/light/RTL with keyboard-visible Close focus. Assertions require 4.5:1 Close text and 3:1 focus contrast against the drawer surface. The title, scrolling region, footer, inline edge, and focus ring were visually inspected. A subsequent visual/motion/scroll run passed 24 executions without snapshot-update mode. These baselines do not cover every theme, density, state, or browser engine.

The shell-drawer-persistence fixture uses a real POST endpoint and app-owned controlled state. Three Chromium cases pass twice each: the drawer stays open and editable during pending closure, rejected persistence preserves focus/draft and exposes retry, retry success closes and restores the toggle, and a save completing after desktop return changes only the phone preference. The fixture coalesces duplicate pending proposals. Explicit owner disposal aborts the exact pending browser request; remounting starts closed with fresh draft/request/error state and a new node. That test pauses outgoing transport, so it proves client cleanup, not rollback of server-accepted work. AppShell never performs persistence or error presentation automatically.

Six motion/placement cases pass twice each in Chromium across LTR/RTL and full, OS-reduced, and scope-reduced preferences. The drawer opens on the correct inline edge at full viewport height, the drawer and scrim use zero duration under either reduced preference, and shell layout has no mount animation. Closing/reopening retains pane identity. Switching the OS preference while open reduces duration without losing pane focus. These are computed-style, geometry, and interaction assertions, not reviewed screenshot baselines. The cases are selected for WebKit, whose runtime remains unqualified.

Delayed registered-pane restoration now has native coverage for data completing while detached, reopening before completion, ready short results followed by growth, explicit keyboard interruption, and superseding the pending route via history traversal. The tests pause and then continue the real transport request, asserting retained DOM identity and both offsets after completion and another drawer reopen. Together with the original route/projection case, six cases pass twice each. This is not evidence for error recovery or every browser engine.

Route-restored panes use the route owner rather than the layout-only offset cache. The initial combined test reproduced Page A's 150/350 offsets appearing on newly navigated Page B, where both offsets should start at zero. AppShell now delegates registered-pane projection to createPaneRestoration, which preserves pending targets while hidden and restores once the pane is visible. The new sidebar-route-restoration case passes twice within a 48-execution Chromium run, covering same-route reopening, detached navigation, back/forward, and desktop return. An earlier main-pane responsive check failed once and passed subsequent isolated/full repeats; its cause remains unestablished.

The shell-sidebar-unsaved fixture uses the actual Solid router adapter and a sidebar editor that registers useUnsavedChanges under the persistent shell owner. Four Chromium cases pass twice each for guard survival across both breakpoint directions and drawer closure, clearing on save or explicit editor disposal, native beforeunload cancellation while the sidebar is detached, and a nested discard confirmation above an open drawer. Cancelling restores the sidebar link and draft; confirming navigates away and removes both overlays without a page error. Closing modal chrome is not editor disposal.

The scroll handoff now has four dedicated native Chromium cases in shell-drawer-scroll.spec.ts, each passing twice. Retaining nodes alone reproduced a reset from 350px to zero on the first drawer projection. The fix retains native pane offsets separately from presentation containers, restores them on insertion, and ignores hidden/detached scroll events. Tests cover both axes in LTR and RTL, both breakpoint directions, modal close/reopen, deliberate scrolling back to zero, and adoption of pre-hydration scrolling. A scoped wide-content fixture verifies bounds clamping when data shrinks while detached and retains the clamped position when more data returns. Identity-based content-change anchors and other engines remain unqualified.

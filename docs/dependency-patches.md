# Owned runtime compatibility

Sheen ships pinned, modified Kobalte core/utils, the CMDK Solid adapter, and Solid's DOM renderer in the UI package. The application retains ordinary `solid-js@1.9.15` for its shared reactive core. There is no vendored second core, install-time patching, or original Kobalte runtime dependency.

Configure `sheenRuntime()` from `@gemologic/sheen/vite` in Vite 8 or SolidStart. It redirects browser `solid-js/web` imports to Sheen's patched renderer, deduplicates the core, and rejects an unqualified core version. SSR keeps the application's pinned Solid server renderer and request-storage pair; Sheen's Node/worker renderer entries delegate to that peer. Copying the server renderer would create a second `RequestContext` symbol, causing Nitro's request storage and SolidStart routing to disagree. Generated apps configure the plugin automatically. Other bundlers need a separately qualified adapter. Direct imports of Solid signals, stores, JSX types, and routers remain normal. Original Kobalte overlays have independent layer/focus state; mixing them into Sheen's stack is unsupported.

`packages/ui/vendor/origins.json` pins upstream tarballs and integrity. `pnpm vendor:runtime` downloads those exact artifacts, applies the repository's `patches/` generation inputs, rewrites backend imports to package-private entries, and retains licenses/notices. `pnpm check:packages` verifies every generated hash and packed export/import target. The workspace no longer applies these patches to dependencies. No consumer scripts or patch configuration are needed.

Run `pnpm test:npm-consumer:browser` after building packages. It installs real tarballs in a clean npm project with unpatched Solid, checks the absence of original backend dependencies, verifies ESM/CommonJS server-renderer identity and asynchronous request-context isolation, and exercises both client conditions plus delayed SSR/lazy hydration. Run `pnpm test:production` against the built Loupe application to check actual Nitro HTTP rendering, cookie request isolation, and delayed browser hydration. CI and publication preparation run both gates. The existing Chromium and WebKit application regressions below remain qualification gates. Pack/typecheck success alone is not runtime proof. Sheen owns requalification and security maintenance of these copies; upstreaming is optional, not a publication dependency. No upstream issue or pull request has been filed by this work.

## Kobalte utils 0.9.2

`scrollIntoViewport` loops through scroll ancestors when document scrolling is locked. Its original next iteration calls `getScrollParent` on the current scrollable element, which returns that same element. Opening a dropdown with ArrowDown inside Loupe's fixed viewport reproduced an unresponsive browser. The ESM and CommonJS patches start the next lookup from the parent element, guaranteeing forward progress toward the document root.

## Kobalte core 0.13.13

Responsive sidebar projection exposed retained floating-layer reactivation bugs. The native failure measured Select content z-index 102, its Popper positioner 100, and the new drawer 101. Popper now observes content style/class changes to synchronize its positioning wrapper, disconnecting the observer and guarding queued work on disposal. Once visual order was fixed, the same retained Select still had pointer-events none because it reopened during its exit lifetime below the newer modal in DismissableLayer's stack. Expanded-state observation now promotes the retained layer and recomputes pointer ownership. Finally, the retained focus scope also needs promotion/resumption when it expands again, otherwise selection returns focus to the parent drawer's first input instead of its trigger. Both JSX and compiled entries carry all three changes.

The two shell-drawer-overlay cases exercise both breakpoint directions, native pointer selection, computed wrapper/pointer order, retained trigger identity, subsequent keyboard reopening/Escape, and parent drawer dismissal. Run these alongside selectors, menus, and floating layers whenever the backend changes. Both JSX and compiled client conditions must pass; compiled-only proof is insufficient for SolidStart.

- Extend `I18nProvider` with an optional explicit direction. ThemeProvider and ThemeScope pass their effective locale and direction separately. Locale still controls collation and formatting; an RTL layout with English text must not silently acquire Arabic formatting or LTR keyboard behavior. Both JSX and compiled runtime entries and the declaration are patched.
- Menu Escape handling now respects `event.defaultPrevented` before recursively closing menus. Sheen's menu layers use that boundary to close only the active submenu and restore its trigger, including when a previous layer is still visually exiting. Both JSX and compiled runtime entries are patched.
- Deferred selectable-list autofocus preserves an already-focused item inside its container. A submenu establishes focus immediately when opening, but the deferred callback could later reset keyboard navigation back to the first item. The JSX and compiled entries now leave established focus alone. DropdownMenu also prevents the separate generic focus-scope autofocus, since the menu's roving-focus machinery owns initial selection.
- Closing animation presence is not input ownership. Closed layers are excluded from Escape and pointer-blocking ownership, and their outside-focus callbacks are ignored. Dialog and Popover opt into focus-scope release/restoration on accepted closure, independently of animation removal. Selectors and menus retain their existing key-release lifecycle so returning focus cannot reactivate a trigger with the same Enter key. Pending mount autofocus is guarded and cancelled on disposal, and exiting nodes cannot restore focus twice. Retained reopening still promotes and resumes its scope. Both JSX and compiled entries are patched. The Dialog and Popover regressions keep a nested exit animation running for ten seconds and require focus restoration plus parent Escape dismissal while that nested node remains attached. Floating-layer tests also run in the WebKit gate.

The live `/menus` browser fixture exercises locked-document keyboard opening, nested light/RTL scopes with English locale, and one-layer dismissal. Run these regressions and the complete browser suite on any replacement version. Do not remove a correction based only on a successful build.

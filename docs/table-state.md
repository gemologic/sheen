# Versioned table state

`parseTableState(value, schema)`, `serializeState(state, schema)`, and `deserializeState(serialized, schema)` own validated state data, not persistence. The v1 JSON envelope is `{ version: 1, state }`. State includes search, filter AST, ordered sorting, pagination, and ordered column layout entries. Each column entry has id, visible, width (positive finite CSS pixels or null for definition sizing), and pin (start/end/false). Pinning uses logical directions.

The schema supplies all available column IDs plus filter/sort definitions. Every available column must occur exactly once in the layout array, whose order defines user column order. Query definitions must refer to available columns. Unknown/missing keys, malformed fields, duplicate/unavailable columns, invalid query references, unknown versions, and malformed JSON fail before anything can be applied. Parsing returns deeply frozen copies. Hidden columns may retain widths and pin positions for later restoration.

Encode the returned string with URLSearchParams through the app's router adapter; never concatenate it into a URL. Encoding and decoding enforce a 262144 UTF-16-code-unit ceiling, not a practical URL length recommendation. No data, accessors, callbacks, credentials, or selection payloads belong in this envelope. Stored filters and column visibility are not authorization controls.

Schema changes currently fail closed. A saved view missing a newly added column or referencing a removed column requires an explicit app migration or a user-visible reset choice. Do not silently discard unknown settings or claim successful restoration. Future state formats need a new supported version and tested migrations, not reinterpretation of v1. Row expansion/grouping state and selection persistence are not included in this version.

Apps provide per-user list/save/delete adapters; no localStorage default exists. `createSavedViews` now supplies request ownership, serialization, validation, retained-list failure, and exact retry, while `createTableUrlState` uses the injected structural router for URL round trips. A table must still retain accepted rows if requesting data for a restored state fails. See [table-views.md](./table-views.md).

`changeTableState(state, change, schema)` applies immutable requested-state updates. Query changes delegate to the query transition rules while preserving column layout. Column visibility, width (including reset to null), logical pin, and exact-permutation reorder preserve query/page state. Sort cycling follows ascending, descending, unsorted; single-column cycling clears other sort entries, while multi-column cycling preserves priority and appends new keys. Sort changes reset page zero. Unknown columns, malformed permutations, and invalid widths fail before applying changes. Five focused transition tests cover these rules; built-package consumers exercise the exported update function.

These state updates do not implement drag handles, keyboard reorder controls, constrained sizing from branded column definitions, or CSS pin/resize rendering. Rendering owners still need to reconcile accepted state and restore focus when a column is hidden.

Five focused state tests cover Unicode round trips, deterministic encoding, copied/frozen layout, hidden/pinned/resized settings, malformed/duplicate/unknown fields, schema drift, version/size limits, continuous mode, and invalid filter/sort references. The URL/saved-view integration adds five real HTTP tests and fourteen repeated Chromium executions. Isolated built-package consumers exercise the public exports. Column controls and full DataTable restore/request rendering remain unfinished.

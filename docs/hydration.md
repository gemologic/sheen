# Hydration event replay

## Contextual portal readiness

The public theme portal accessor returns no target until the provider's mount handoff is ready. A target ref alone is insufficient: inserting a persistent portal while the parent is still hydrating can have its children removed by the parent's hydration pass. Toaster's delayed-script regression queues a notification before hydration, verifies that it appears in the ready contextual target, and checks that the original trigger DOM survives. Shared overlay regression qualification remains required whenever this readiness boundary changes.

Loupe uses SolidStart's HydrationScript in the document assets, separately from the theme prepaint script. The theme script owns colors; Solid's bootstrap queues pre-hydration click/input events.

DataTable renders its accepted server rows, native row-selection checkboxes, group/hierarchy expanders, column order, concrete grid tracks, and resize widgets in the server document. Hydration adopts those nodes instead of clearing them. A pre-hydration native checkbox change is reconciled into table selection after mount without replacing the focused input or emitting duplicate intent. A pre-hydration hierarchy-expander click is replayed against that same focused button and parent row. Default-expanded unloaded subtrees do not dispatch during SSR; their app-owned requests begin only after the mounted handoff. Transient pointer-resize custom properties do not exist until an interaction; committed layout is stable state, and data refreshes retain it independently of the request lifecycle. Delayed-script coverage focuses and marks server-rendered row and control nodes, then verifies identity, focus, checked or expanded state, and absence of a duplicate initial server request through hydration.

FilterBar renders accepted chips and its native triggers in the server document, but its editors mount only after the contextual portal is ready. Solid queues a trigger click made before JavaScript. Hydration reuses that marked server button and opens exactly one editor; it does not replace the bar or dispatch a provisional filter. Editor drafts begin after hydration and publish only on Apply. A delegated DataTable with `initialResult` continues to skip an initial duplicate request.

DataTable export triggers are deterministic server markup. A queued pre-hydration trigger click opens exactly one contextual menu after adoption, while `onExport`, Blob creation, and object-URL publication remain client-interaction work. Export pending and failure states do not replace accepted rows; frame-sampled browser coverage asserts no blank table body during a real delegated export. Changing `export.resetKey` aborts and revokes retained artifacts at authorization boundaries.

Editable DataTable cells server-render only their committed focusable spans. A queued click opens one uncontrolled native editor after hydration without calling `onCellCommit`; a server span already focused before adoption is detected when its listener attaches and enters the same state. Validation, pending work, a changed refetch, transport failure, conflict, and superseding commit retain that input node and its DOM draft. `editResetKey` deliberately tears down those owners at authorization boundaries.

DataTable row context actions also hydrate onto the retained server row. Before JavaScript, no replacement menu exists and the native context menu remains available. After the contextual portal becomes ready, right-click, `Shift+F10`, or the platform Context Menu key opens exactly one scoped menu; Escape returns focus to the same row. Cold-load and refresh timers start only after mount. Revalidation retains accepted row DOM and shows no loading treatment under 500 ms, then adds a progress/status layer without dimming or replacing content.

NumberField, Slider, and RangeSlider emit complete localized values and native controls during SSR. NumberField adopts a valid pre-hydration edit from the live input property; hydration does not replace the marked input or range thumbs. Tree emits its complete hierarchy server-side, retains collapsed groups with `hidden` and `inert`, and adopts the same roving item nodes and expansion state. Real delayed refresh fixtures for both families sample intermediate frames and require retained DOM identity rather than accepting a matching final screenshot after a flash.

Immediately after the framework bootstrap, Loupe emits `createKeyboardHydrationScript()`. This opt-in script queues Select arrow/typeahead and DropdownMenu trigger keydowns in Solid's existing hydration queue and prevents their pre-JS browser scrolling. It ignores modifiers/composition and does not queue Enter/Space, because native buttons already generate the clicks that Solid queues. Queuing both would activate twice. Emit this script before interactive markup, with the app's CSP nonce when required. Scaffolds and dogfood apps must carry this bootstrap too; without it, early custom keyboard navigation is not replayed. It does not make a no-JavaScript listbox or menu available.

## Sheen-owned Solid 1.9.15 DOM renderer

The UI package ships the patched DOM renderer from `solid-js@1.9.15`. Configure `sheenRuntime()` from `@gemologic/sheen/vite` in Vite/SolidStart; the plugin redirects browser `solid-js/web` imports and keeps the application's ordinary Solid core shared. SSR remains on the peer server renderer so `solid-js/web/storage` and routing share one request context; Sheen's server export delegates to the same peer. `pnpm test:production` qualifies actual Nitro SSR and delayed hydration, not only a successful build. The `patches/solid-js@1.9.15.patch` file is a vendoring input, not consumer patch configuration. Browser development/production ESM and CommonJS delegated event handlers use the composed path only when that path contains elements. An event replayed after its original dispatch has an empty `composedPath()` in Chromium. The original handler entered the path branch, visited no nodes, and consumed the queued event without invoking its handler. Falling back to the existing event-target traversal fixes that case while leaving live composed-path dispatch unchanged.

This was reproduced with real scripts held behind a browser request barrier: clicking Save before hydration queued the event, hydration drained the queue, and the count remained zero. The same scenario passes with the patch. The regression also queues a scoped dialog trigger and checks a subsequent live click for duplicate handling. Do not replace this test with a wait for hydration before clicking.

The patch also prevents delegated events from marking hydration complete while Solid's pending lazy-component count is nonzero. Imported components install document-level handlers before all route modules arrive. An unqueued pointer/focus event could set `sharedConfig.done` during that interval, causing the delayed route to render fresh client DOM instead of hydrating its server nodes. Native drafts and queued clicks were then lost without a mismatch exception. The DescriptionList regression holds only its route module, waits for the real delegated listeners to exist, hovers/types/clicks the server DOM, then releases the module. It failed before this correction and passes with retained node identity, retained draft, and exactly-once click replay. Holding every script would miss this partially hydrated interval.

The same renderer ships to npm consumers; generated apps configure the setup plugin automatically. `pnpm test:npm-consumer:browser` runs real clean npm artifacts with unpatched Solid and tests both completely delayed scripts and a partially hydrated lazy route. It checks retained draft/focus/server nodes, exactly-once replay, intermediate frame continuity, and the actual development module graph. Keep the plugin enabled. Replace the owned renderer only after these regressions and the application browser gates pass against the replacement. No upstream issue or pull request has been filed by this work.

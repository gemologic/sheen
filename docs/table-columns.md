# Opaque table columns and row identity

`defineColumns<Row>(definitions)` validates sheen-owned column fields and returns `SheenColumns<Row>`, an opaque branded value rather than an array or TanStack type. Apps cannot inspect or mutate normalized definitions. The eventual DataTable adapter is the only consumer of the package-internal projection, so an upstream table change remains a single translation seam.

Every column has an explicit unique, nonempty, trimmed ID and visible string header. This follows [TanStack's requirement for explicit IDs on function-accessor columns](https://tanstack.com/table/latest/docs/guide/column-defs), without exposing its definitions. Accessor columns may declare search, filter, sort, aggregation, formatting, sizing, visibility, alignment, and logical pinning. Display columns require a cell renderer and cannot search, filter, sort, or aggregate. Pin values use `start` and `end`, matching both sheen's RTL contract and [TanStack v9's logical pinning change](https://tanstack.com/table/latest/docs/framework/solid/guide/migrating).

Global search is opt-in per accessor column. `search: true` uses its scalar accessor; a function supplies a dedicated finite-number or string projection for safe domain labels. Initially hidden columns, display/action columns, and columns marked `sensitive: true` cannot declare search. Dynamically hiding a searchable column is a layout preference and does not silently change the accepted query. Projection results are validated at evaluation time and arbitrary values are never coerced through `toString`.

Widths are positive fixed CSS pixels, `fill`, or `content`, with optional positive min/max bounds. Numeric columns default to end alignment and numeric sorting. Otherwise sorting derives from the filter type or defaults to text; explicit false disables it. Non-count aggregates require a numeric declaration. Enum options are copied, deduplicated, and retain the separate `faceted` flag. Runtime accessors accept only strings, finite numbers, booleans, or null.

`__unsafe_tanstack` is the only table-engine escape-hatch field. It is a typed unknown-valued record, copied and shallow-frozen under the normalized definition. It is deliberately explicit, greppable, and lint-warned. The core renderer does not interpret it; any separately qualified TanStack adapter must narrow supported keys against its pinned types. This seam does not claim upstream runtime compatibility.

`createRowIdentity(getRowId)` resolves a complete row array into frozen `{ id, row, index }` records while preserving row objects. It rejects empty/whitespace IDs, duplicates, sparse/non-object rows, and an ID change for the same object across resolutions. A replacement object may reuse an existing ID after refresh. `clear()` resets object-history checks for an intentional dataset/account identity boundary; it does not authorize reuse of cached rows.

Three column tests and two row-identity tests cover normalization, opacity, schema projection, search projections and exclusions, copied escape-hatch/options, inferred defaults, invalid fields/dimensions/aggregates/accessor values, stable object IDs, replacement objects, duplicates, sparse inputs, and explicit reset. The isolated built-package consumer verifies the public brand and row resolver without importing TanStack.

# DataTable dependency qualification

Checked and production-profiled on 2026-09-08. The dependency choices and replacement boundary are approved.

The npm registry reports `@tanstack/solid-table` 9.2.4 as latest, published 2026-08-28, MIT, with Solid peer >=1.3. Its dependencies are table-core 9.2.4 and TanStack Store ^0.11.1. `@tanstack/solid-virtual` 3.13.37 was published 2026-08-18, MIT, with Solid peer ^1.3.0 and virtual-core 3.17.8. These peer ranges include this workspace's pinned Solid 1.9.15. Both direct releases exceed the workspace's 1440-minute minimum release age; all transitive selections must still pass installation policy.

The [current Solid Table documentation](https://tanstack.com/table/latest/docs/framework/solid/quick-start) describes v9 createTable, explicit feature registration, and TanStack Store-backed state. The [Solid migration guide](https://tanstack.com/table/latest/docs/framework/solid/guide/migrating) documents the API changes from v8. Existing spec reference links to v8 do not prove v9 behavior. Since sheen does not yet depend on Table, using v9 would avoid building a new internal wrapper against the previous major. The tradeoff is the newer API and Store dependency, both needing local SSR/reactivity and bundle qualification.

[Solid Virtual](https://tanstack.com/virtual/latest/docs/framework/solid/solid-virtual) provides element-scoped createVirtualizer, matching the spec's pane scrolling. We do not want window virtualization for desktop AppShell tables. Its headless rendering leaves sheen responsible for table semantics, focus realization, row identity, measurement, scroll anchoring, and blank-frame tests.

Both candidates were initially approved and qualified. The production 100,000-row profile then showed `@tanstack/solid-table` constructing a second full row model after Sheen had already searched, filtered, sorted, and identified the same data. That allocation and its caches dominated the UI path and added no state ownership the public API needed. The core renderer therefore uses a Sheen-owned lazy display-row projection and keeps only `@tanstack/solid-virtual` 3.13.37 at runtime. The public `__unsafe_tanstack` field remains a typed, lint-warned compatibility seam for a separately qualified adapter, not behavior consumed by the core renderer.

This replacement reduced the production Loupe DataTable chunk from about 314KB raw and 68.9KB gzip to about 229KB raw and 48.4KB gzip while cutting the observed 100,000-row mount from about 289ms to a five-run median of 110.5ms and the multi-sort interaction from about 228ms to 101.8ms. Direct two-key sorting remained about 35–41ms. Delayed hydration, replacement-row refresh, fixed and variable-height virtualization, keyboard scrolling, retained row identity, and isolated built/source consumers are qualified independently by their focused suites.

# Loupe theme editor

`/theme-editor` authors a complete `ThemeDefinition` inside a retained `ThemeScope`. The editor starts from the dark-default Obsidian tokens, exposes every semantic token, and keeps dark and light values in the same document. Color values have OKLCH lightness, chroma, hue, and alpha controls; every token also has a raw CSS-value input for units, type, motion, and other non-color values.

Live edits are structurally validated with `resolveTokens` before acceptance, then emitted into one editor-owned `<style>` element appended last in the document head. Writes are collapsed to one animation frame and call the Loupe-only chart-token invalidation hook after the CSS lands. The preview scope, its form draft, and its canvas remain mounted. Contrast and chart-palette failures are diagnostics, not edit rejection, so an author can inspect and repair a failing intermediate state. Export is stricter and runs the complete `defineTheme` gate.

Derivation operates one mode at a time. Supply an opaque background in the expected lightness range, one of the twelve audited accent presets, and a neutral hue. Loupe generates related surfaces, accessible foreground/control tones, focus tokens, neutral roles, and chart chrome while retaining the rest of the current document. Derive both modes before exporting when both should share the new neutral direction.

Import accepts either plain JSON matching `ThemeDefinition` or the exact `*.theme.ts` envelope generated by Loupe. It parses the enclosed JSON and passes the result through `defineTheme`; it never imports, evaluates, or interprets arbitrary TypeScript. Export produces a complete, validated module using `defineTheme` from `@gemologic/sheen-tokens`.

Work in progress uses the versioned `sheen:loupe:theme-editor:v1` localStorage key. Reads and writes are guarded, so blocked or corrupt storage leaves the editor usable and reports the recovery status. The server and initial hydration tree intentionally render an opaque dark loading boundary. Client-only recovery happens behind that boundary, preventing a default-theme preview from flashing before a stored document is known.

Focused coverage lives in `tools/theme-editor-state.test.ts` and `tests/browser/theme-editor.spec.ts`. The pure tests cover derivation, intermediate contrast failures, OKLCH channels, and the non-executing import/export round trip. Chromium coverage verifies opaque retained refresh frames, component and canvas identity, real storage recovery after reload, a generated-file download, executable-source rejection, and delayed-JavaScript hydration.

# Inline table editing ownership

`createCellEdit(initial, onCellCommit, options?)` owns one scalar cell's committed value, local draft, validation, commit ordering, refetch state, transport failure, and explicit version conflict. Supported values are strings, finite numbers, booleans, and null. The callback receives a monotonic bigint `commitId`, captured value and previous committed value, plus an AbortSignal. A resolved result is either `{ kind: "accepted", value }` or `{ kind: "conflict", current, detail }`; transport failures reject.

`begin()` creates an uncontrolled editing draft from the committed value. `setDraft()` never mutates the committed value. A synchronous validator returns a nonempty message or null. Invalid commits retain the editor and draft without invoking transport. Render `invalid` through `data-invalid` and the field's accessible error relationship.

Transport failure retains both the committed value and failed draft, sets `error`, and keeps editing active. The DataTable renderer must flag the cell and send a toast with retry. `retry()` is permitted only while the draft is exactly the failed attempt; it returns `changed` after a newer draft so an old retry cannot overwrite new work. Each actual retry receives a new commit ID. Successful completion closes the editor only when its captured draft is still current.

`acceptRefetch(value)` updates the committed value. During editing it preserves the local draft and sets `stale` once the refetched value differs from the edit base. Render this as `data-stale` and keep it visible until a successful commit or `discard()`. A conflict adopts the app-reported current value behind the editor and remains in `conflict` until commit/retry or discard. Sheen does not infer version conflicts from transport text.

Starting another commit aborts the prior operation and uses a monotonic ownership token; a late result cannot publish even when abort is ignored. `discard()` and `dispose()` likewise suppress late publication. Abort does not undo arbitrary adapter side effects. Clear all cell controllers at account or authorization boundaries.

Six real HTTP tests cover synchronous validation, success, transport failure/retry, changed-draft retry rejection, stale refetch, explicit conflicts, duplicate pending submission, superseded ignored-abort results, and disposal.

Accessor columns opt into DataTable editing with `editor: { type }`. Text, number, boolean, and select editors use native controls; select requires unique nonempty options, and text/number/select may opt into null. The resting cell is a focusable span containing only the committed presentation. Focus, click, or Enter swaps it for an uncontrolled editor. Enter and blur commit, Escape discards, and Tab follows native document order into the next editable cell while the prior cell commits. Forms must consume app-owned committed data rather than reading these transient DOM controls.

Editable tables require `onCellCommit(request, signal)`. The request extends the controller snapshot with the stable `rowId`, column ID, and captured row. Commit IDs are monotonic per row/column cell. A returned value must match the declared editor type; malformed results fail without replacing committed presentation. The app updates its data source when appropriate, while DataTable can present the accepted value immediately and reconcile a later refetch.

DataTable keeps one controller per encountered row/column cell outside the virtualized renderer, so a retained draft is not tied to a particular DOM window. A refetch updates committed presentation behind a dirty editor, preserves the uncontrolled DOM value and focus, and marks the cell `data-stale`. Transport failure sets `data-invalid`, retains the draft, and raises a persistent toast whose retry is valid only for the same draft. Explicit conflicts adopt and display the app-reported current value while retaining the draft and `data-conflict`; a newer draft requires a new commit. `editResetKey` disposes all controllers, aborts pending work, clears editing toasts, and reconstructs committed cells at account or permission boundaries.

SSR emits only committed focusable spans and never calls `onCellCommit`. During delayed hydration, an early click is replayed once and opens one editor without a provisional request. An element focused before its listener is attached is adopted and begins editing after hydration. Editor state changes update attributes in place rather than replacing the input, so validation, pending, stale refetch, conflict, and superseding commit transitions do not flash an empty cell.

Six real HTTP controller tests and DataTable SSR/column tests cover synchronous validation, success, transport failure/retry, changed-draft retry rejection, stale refetch, explicit conflicts, duplicate pending submission, superseded ignored-abort results, disposal, editor schema validation, and deterministic resting markup. Seven Chromium cases cover queued hydration, validation, real transport failure/toast retry, focused draft preservation across refetch, explicit conflicts, ignored-abort supersession, native Tab traversal across every editor type, and authorization reset. A reviewed dark conflict baseline confirms the inline error remains visible without replacing the row. Cross-engine behavior and application-specific conflict-detail presentation remain release/dogfood boundaries.

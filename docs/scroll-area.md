# ScrollArea implementation boundary

The pinned `@kobalte/core@0.13.13` package has no ScrollArea export. The spec's reference to that primitive cannot be implemented as written. Sheen therefore owns a native scrolling viewport with no new dependency. Its overlay tracks and AppShell's desktop-pane/phone-document integration are implemented and qualified.

Give every viewport a required accessible `label` and constrain its size through the parent grid/flex chain or explicit dimensions. `orientation` permits vertical, horizontal, or both axes. The forwarded native `ref` identifies the actual scrolling element, not a wrapper. Its default region role and Tab stop provide native keyboard scrolling; wheel, touch, and RTL coordinates remain browser-owned. No scroll position is reset on mount, hydration, or ordinary content updates.

The viewport exposes `data-scrolling` during scrolling and clears it after 800ms idle. Native scroll callbacks are forwarded. An outer grid frame holds 8px overlay tracks without reserving a native scrollbar gutter. The forwarded ref still points to the actual native viewport; native attributes/classes/styles remain on that viewport. Content stays mounted inside a flow-root measurement wrapper.

Thumb length and position are measured from native client/scroll dimensions, updated in animation frames, and observed for viewport/content resizing and ancestor direction changes. Pointer capture supports dragging outside a track; track presses center the thumb at the pointer. Horizontal movement respects native RTL coordinates. Tracks are pointer affordances hidden from the accessibility tree; the named native viewport remains the keyboard scrolling interface. Tracks appear on hover, focus within, or scroll/drag activity and fade using motion tokens after idle. Reduced-motion tokens remove the fade. Timers, animation frames, and observers are owner-cleaned.

The current browser checks cover vertical dragging, RTL horizontal dragging, track jumps, resize response, zero native gutter, fade, native scrolling, and hydration retention. A bordered, fixed-width two-axis fixture reproduced tracks incorrectly following the wider frame. Tracks now follow the viewport's inner border box, reserve their shared corner on the correct RTL side, and update after direction changes. Pointer distances are normalized against rendered track bounds, with an ancestor-scale drag regression. A reviewed RTL baseline covers this geometry, not full contrast qualification.

When refreshed content removes overflow during a drag, the component cancels that drag and releases pointer capture explicitly. A real delayed-response browser regression verifies the active state clears and a subsequent drag works after overflow returns. A separate disposal test records native pointer capture, removes the whole viewport while the pointer remains down, verifies the detached track no longer holds capture, and drags a freshly mounted instance without browser errors.

Forced-colors mode uses the system Canvas track, CanvasText thumb, and Highlight focus outline without opting out of browser color adjustment. Chromium emulation reproduced a translucent white thumb before this correction; the regression switches between light and dark palettes, checks both thumbs remain distinct from their tracks, and verifies visibility, automatic color adjustment, focus outline geometry, and native PageDown scrolling. This follows the [CSS Color Adjustment specification](https://www.w3.org/TR/css-color-adjust-1/#forced-colors-properties). Physical operating-system high-contrast palettes still need qualification.

Viewport-only transforms, rotation/skew, full visual/contrast and cross-browser qualification remain open. AppShell suppresses overlay tracks in mobile document-flow mode.

This primitive does not virtualize content, fetch data, restore routes, or lock document scrolling. AppShell supplies constrained panes, desktop document locking, and the below-768px document-scroll fallback. Per-pane router restoration remains a separate shell obligation.

The `/scroll-area` fixture exercises native PageDown and wheel input, RTL horizontal scrolling, idle state, retained drafts/viewport identity across refresh, and delayed-JS hydration preserving pre-hydration scroll. Refresh-position comparisons wait for scroll idle so they do not confuse the tail of native keyboard-scroll animation with a refresh reset.

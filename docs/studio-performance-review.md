# Studio performance qualification review

Status: the user explicitly approved the theme-switch baseline on 2026-09-16. Applied as a new history entry in `bench/baselines/admin-app.v3.ts`. Three final normal admin benchmark repetitions pass. Final starter checks passed 78 Chromium and 78 WebKit cases; Q4 local qualification is complete.

The previous admin benchmark started with the inherited Obsidian theme and switched to Graphite. Both use Plex. The approved starter now begins with Studio and Inter, so the same control also changes font family, font weights, and text sizes. The benchmark still exercises that complete transition.

Five interleaved diagnostic pairs on the current production build measured median layout CPU of 13.166ms for Studio → Graphite and 1.006ms for Obsidian → Graphite. These diagnostics isolate the changed rendering work; they are not regression qualification. Raw paired samples are in `/tmp/sheen-theme-comparison.json`.

Before approval, the normal benchmark failed its original theme-switch CPU limit. The last three five-run measurements were 0.3207, 0.3234, and 0.3365 against 0.3188. No failure was rounded away or discarded. Correctness fixes made during profiling include retained appearance/history state, stable navigation models, locale-specific formatter dependencies, fewer unstyled numeric elements, and correct canvas axis fonts at pixel ratios 1 and 2.

## Qualification after approval

All three initial normal repetitions passed the approved theme-switch limit (0.3602 / 0.3794 / 0.3837), with every frame, layout-shift, retention, and footprint gate intact. They failed other unchanged CPU limits: sidebar collapse in all three, refresh in all three, details dock in two, and table search in one. These failures remain recorded in `/tmp/sheen-style-admin-approved.log`; the complete artifacts were preserved in `/tmp/sheen-style-qualified-bench/`.

Both final consumer gates passed: `pnpm test:consumer-browser` and `pnpm test:npm-consumer:browser`, including all ten packed packages and native Chromium SSR/hydration interactions. The affected chart and table benchmarks passed their unchanged budgets (59.2s and 30.4s). Final runtime integration had already passed `pnpm check` with 710 unit tests; baseline ESLint and `git diff --check` also passed.

Refresh tracing identified repeated full-body accessibility snapshots generated by Playwright while the future revision label was absent. The benchmark now waits for the existing revision label's exact text to update, then asserts visibility. All refresh correctness/retention checks and measurement boundaries remain inside the sample. See [the sampling documentation](benchmark-sampling.md). This is a harness correction, not a refresh budget increase.

Further focused tests reproduced replaced action icons on preview changes and redundant chart token reads on sidebar changes. The starter now retains its action model while updating link destinations, suppresses equal theme overrides, and publishes selected-account/open state atomically. The search benchmark scopes its existing accessible-name lookup to the accounts table. Production build, root/Loupe typecheck, lint, the strengthened native identity test, and all 26 production tests passed.

The final normal command, `SHEEN_ADMIN_BENCHMARK=true SHEEN_BENCHMARK_PORT=4187 sheen-browser -- --config bench/playwright.config.ts --repeat-each=3`, passed all three five-run measurements in 1.4 minutes, with capture mode unset and no tracing/profiling.

# AppShell layout foundation

`AppShell` lives in `@gemologic/sheen-patterns`, composing `@gemologic/sheen` primitives. Load both packages' styles. A separate `@gemologic/sheen/metadata` entry supports build-time metadata without importing it into component runtime entry points. The new workspace package adds no external dependency versions.

Supply a required primary-content `label`, normal content children, and optional `header`, `sidebar`, and `statusBar` slots. Slots resolve once and preserve their owners. The shell creates native header/aside/main/footer landmarks and a named ScrollArea for primary content. Sidebar content can supply its own named ScrollArea. `--sheen-shell-sidebar-width` controls the desktop column, defaulting to 16rem.

Header and footer have explicit banner and contentinfo roles. The desktop aside uses the shell's content label as its accessible name, retaining its native complementary landmark inside a theme section, as specified by [HTML accessibility mappings](https://www.w3.org/TR/html-aam/#el-aside). AppShell is an application frame, not a layout to nest inside another application's main landmark.

At 768px and above the shell fills 100dvh, constrains every grid track, and uses CSS document locking when the shell is present. Header and status chrome stay outside the scrolling content. The styles apply before JavaScript, and native pane refs/DOM survive hydration. Use one full shell per document; compare shells inside separate iframes.

Below 768px the primary pane becomes document content and scroll chaining is permitted. CSS hides the desktop sidebar before JavaScript; after hydration its retained content is projected into a scoped modal drawer. Sidebar-bearing shells require ThemeProvider. The visible responsive toggle does not require ShortcutProvider; enabling shortcutHelp additionally registers the keyboard binding.

Desktop sidebarOpen/defaultSidebarOpen/onSidebarOpenChange and phone mobileSidebarOpen/onMobileSidebarOpenChange are independent. Local desktop state defaults open; local phone state starts closed and resets when returning to desktop. Controlled phone state remains app-owned and can reopen on returning to phone if the app keeps it true. Dialog content uses a stable contentId for aria-controls. A desktop editor displaced by the phone breakpoint returns focus to the mobile toggle, without taking focus from another pane. Closing the drawer or returning to desktop restores the appropriate surviving toggle.

Thirteen Chromium shell cases and five shell SSR tests pass for the initial integration, including retained sidebar drafts/nodes, closed first phone paint, queued toggle hydration, Tab wrapping, Escape, background accessibility isolation, responsive focus recovery, and independent desktop behavior. Two additional controlled-phone cases pass alongside the three existing drawer cases: rejected Escape, close-button, and backdrop proposals retain modal focus/drafts; accepted closure restores the trigger without changing desktop state; a controlled open preference survives desktop presentation and reopens on phone without synthetic close proposals. These are synchronous app-acceptance tests, not transport persistence tests. RTL visual matrices, nested overlays during resize, async persistence, scroll anchors across projection, and other engines remain unqualified. See docs/sidebar-handoff.md for the retained-owner approach and docs/shortcuts.md for registry ownership. This is not a release-complete shell.

The `/shell` fixture verifies independent desktop pane scrolling, fixed chrome, retained drafts/scroll on refresh, initial constrained markup under delayed JavaScript, and real phone document-wheel scrolling. Loupe's older broad `main` rule excludes the shell's main grid cell so it cannot introduce a second scroll container or unwanted padding there.

Sidebar editors may register useUnsavedChanges under their retained owner. Moving between desktop and drawer, or closing the drawer, does not release that registration. Saving the editor or disposing its owner does. Four native Chromium cases, repeated twice, verify router blocking across these transitions, beforeunload while detached, and nested discard confirmation above the open drawer. Cancellation restores its initiating sidebar link and draft; confirmation navigates and removes both overlays.

Sidebar panes registered through usePaneScrollRestoration retain route ownership across projection. Their route target takes precedence over layout-only retention, including when navigation occurs while the drawer is closed. Hidden or detached panes cannot overwrite saved route offsets or prematurely finish restoration against zero-sized layout. On projection, the route owner restores the pending target or the current route's accepted offset. Native coverage verifies same-route reopening, new-route reset, history back/forward, and desktop return with both axes and retained node identity.

Sidebar ScrollArea offsets now survive desktop/drawer projection and drawer close/reopen through an AppShell-owned weak cache keyed by the retained pane element. Each presentation container captures visible native scroll events and restores saved offsets on mount; zero offsets emitted while hidden or detached are ignored. Initial mounting adopts existing server-pane offsets, including scrolling before hydration. Four Chromium cases pass twice each for horizontal/vertical scrolling in LTR and RTL, both breakpoint directions, drawer reopening, and a deliberate return to the top. The scoped wide-content fixture also verifies clamping after detached content shrinks and retaining that clamped offset when data grows again. This does not yet qualify identity-based row-anchor restoration after content changes or WebKit/Firefox.

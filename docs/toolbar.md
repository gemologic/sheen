# Toolbar implementation boundary

The initial public Toolbar component is exported by `@gemologic/sheen-patterns`. Load the patterns stylesheet alongside sheen styles. Supply a nonempty label and ordered groups with stable IDs, group labels, and core sheen action/checkbox item definitions. The optional filter slot stays mounted outside the action toolbar's keyboard navigation.

Allocation preserves group order and never splits groups. If every group fits, no overflow-trigger width is reserved. Otherwise the allocator reserves the trigger and fits the longest leading prefix, moving whole trailing groups into overflow. Fractional CSS pixels are retained without rounding. At extremely narrow widths it reports the trigger's minimum width even when the allocated region cannot contain it; the component must wrap surrounding slots or otherwise provide that minimum, never hide access to overflow actions.

Six unit cases cover exact-fit and fractional boundaries, invalid measurements, whole-group ordering, trigger-only layouts, and a deterministic 1,001-width sweep checking partition, fit, maximality, and monotonicity. This proves the allocation rules, not browser measurement or focus behavior.

The component measures group and trigger widths with ResizeObserver, schedules allocation in animation frames, and renders overflow through the scoped DropdownMenu. Groups stay mounted in inert hidden measurement positions when overflowed. Actions and toggles use app callbacks and controlled checked state. The filter slot occupies a separate row and retains native text editing. Action controls use a single toolbar Tab stop, horizontal arrows, Home/End, disabled skipping, and RTL direction, following the [WAI-ARIA toolbar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/).

SSR initially exposes the overflow trigger while inline groups remain inert and measurable. Hydration measures available space and promotes fitting groups. Promotion pauses while the overflow trigger is focused, retaining the menu's existing action set for queued activation. A resize that hides a focused inline action transfers focus to the overflow trigger. Allocation stays frozen while the menu is open and through its close-focus lifecycle. DropdownMenu exposes `onCloseAutoFocus` for this coordination; no timing delay guesses when focus restoration completes.

Seven browser cases cover inline/overflow toggle invocation, enabled-action roving, single Tab stop after resize, retained filter drafts, native RTL/filter keys, and a queued overflow activation that invokes its original action after delayed hydration. A real delayed response removing the focused inline action recovers to the next enabled survivor, then the previous one if necessary, or the toolbar when empty. Reversing groups retains the focused DOM node and updates arrow navigation; disabling the focused action recovers to a successor in the new order. An outside focus move or pointer interaction prevents recovery from stealing focus back. Keyboard focus on the empty toolbar has a visible outline. Open-menu resizing preserves action identity through actual activation and restores focus before promotion resumes. SSR and metadata/examples are checked.

DropdownMenu now handles focused item removal in its own content layer, recovering to the next enabled survivor, then the previous one or the menu container. This shared handling covers Toolbar overflow and nested submenus. Real delayed-response regressions verify continued keyboard invocation after removal in both cases; parent and nested menu ownership remain separate. The combined menu/Toolbar run passes 15 browser cases.

If refreshing groups empties an open overflow menu, Toolbar closes it and handles the close-focus lifecycle before choosing a surviving inline action or the empty toolbar as fallback. Focus already moved outside is preserved. A real request regression clears every action, verifies menu dismissal and fallback focus, then restores actions and successfully invokes Save through overflow again. The Toolbar suite now passes ten browser cases.

Hidden groups are contained by zero-size clipped wrappers; their full-size inner content remains measurable and mounted. A real narrow-layout test reproduced 68px of unwanted horizontal overflow before this correction and now verifies zero extra scroll width in both directions. Width allocation subtracts 4px focus-ring clearance on each inline edge. A geometry regression and reviewed dark/light RTL baselines cover the formerly clipped first-action ring.

The 80px fixture reproduced 33px of overflow from the trigger itself. Its label now wraps against the action container's inline size using container-relative units, including when its outer measurement wrapper is hidden. The extended narrow regression verifies RTL scroll width, text bounds, and keyboard reopening after a direction change. That reopening exposed a shared portal-target bug: reactive attribute spreads could remove overlay-owned children. Explicit root/scope target attributes fix it. Twenty combined menu/Toolbar browser cases pass, with existing screenshots unchanged, plus two direct open-menu theme-update regressions preserving DOM identity, focus, and invocation.

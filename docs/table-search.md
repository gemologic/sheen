# Ranked client search

`searchClientRows(rows, query, { locale, columns, getValue })` returns `{ row, rank }` matches in ascending rank order, retaining original row objects and source order for ties. Only configured columns participate. Normalize strings to NFC and explicit-locale lowercase, split the query on whitespace, and deduplicate terms. Every distinct term must match at least one column; terms may match different columns.

Set `exactMatch: true` to enable the portable exact syntax. A leading apostrophe disables fuzzy ranking and matches one case-insensitive literal phrase contained within a configured searchable column. For example, `'Aperture` matches `Aperture 001`, and `'Ada Lovelace` matches both `Ada Lovelace` and `Dr. Ada Lovelace`. It does not split a phrase across columns or allow missing, reordered, or noncontiguous characters. Use a text column filter with `is` when the complete cell must equal a value. Two leading apostrophes search for a literal apostrophe. `parseSearchQuery` and `formatSearchQuery` expose the same encoding to server adapters without adding a nonserializable matcher or a second state channel. DataTable's `search={{ exactMatch: true }}` renders a visible Smart/Exact menu and typing the apostrophe updates that control automatically.

Per term, the best column match scores exact = 0, prefix = 1, substring = 2, ordered subsequence = 3. Sum term scores for the row rank. This intentionally small matcher supports abbreviated subsequences, not edit-distance typo correction. Accents are retained. Subsequence iteration handles complete Unicode code points rather than splitting surrogate pairs. No regular expression is constructed from user text.

String values and finite numbers are searchable. Numbers use locale-independent raw numeric strings; format dates or domain labels in an app-owned search accessor when needed. Null, undefined, booleans, nonfinite numbers, arrays, and objects do not participate. Arbitrary toString methods are never invoked. Blank queries return all rows with zero rank without invoking accessors. A nonblank query with no search columns returns no matches. Accessor errors propagate.

Search the complete client dataset, then apply filters, compute facets, apply explicit sorting if present, and paginate last. Explicit sorting takes precedence over relevance, retaining relevance order for equal sort keys. Server mode delegates search as part of its complete query, never searches only the loaded page. Apps must clear old-user data on authorization boundaries.

Five focused tests cover ranking/stable identity, multi-column terms, column exclusion, duplicate terms, Turkish casing, NFC, emoji subsequences, blank queries, finite numeric values, invalid columns/locale, and accessor errors. Public built-package consumer checks exercise the export.

## Trailing scheduling

`createDebouncedSearch(query => searchClientRows(currentRows(), query, options))` schedules synchronous client evaluation after 120ms by default. Each request returns a promise that settles as accepted, failed, superseded, cleared, or disposed. Rapid requests cancel the prior timer and settle its promise without evaluating it. The callback reads the latest complete dataset when the timer fires, not an implicit captured row snapshot. It is a synchronous compute callback, not a remote request hook.

`getSnapshot()` exposes accepted query/results separately from the requested query, pending flag, and error. Accepted results retain identity during pending work and failure. `retry()` retries the failed requested query, including an empty string. `clear()` cancels pending work and removes accepted results immediately; `dispose()` also prevents future requests. Reentrant requests/clears during evaluation cannot publish obsolete results. The controller owns no subscription or Solid owner: UI adapters publish snapshots before and after awaiting requests and dispose it on cleanup. Clear it and stop old producers at account/permission boundaries.

The optional third argument `{ query, result }` adopts already accepted initial results without evaluating or scheduling work. It copies the query wrapper and retains result identity. Apps supply identical serialized initial data to server and client, including already accepted ordering. The generic controller cannot validate a domain result or infer whether it matches the query; that remains the caller's responsibility.

Eight real-timer tests cover initial adoption, trailing/default delay, supersession, retained accepted identity, failure/retry, empty queries, clear/dispose settlement, reentrant evaluation, latest-dataset reads, and delay validation. Isolated public-package consumers exercise both matching and scheduling.

The `/table-search` Loupe fixture composes the lower-level controller with SearchInput and stable-ID rows. The public DataTable now owns the equivalent application path. Search appears when at least one column explicitly declares `search: true` or a validated search projection. `search={false}` disables the capability; an options object supplies the caption-specific accessible label, placeholder, trailing delay, optional registry-backed focus shortcut, and exact-match opt-in.

Column-specific matching remains FilterBar's job. Text columns already provide `is`, `contains`, `starts with`, `ends with`, case sensitivity, and negation, while enums, numbers, and dates retain typed editors. Sheen does not run arbitrary native `RegExp` patterns over client rows: short pathological expressions can monopolize the browser main thread. Regex belongs in a bounded server adapter or a separately approved linear-time matcher with explicit validation and performance gates.

The input keeps a separate draft while accepted state and rows remain coherent. IME composition never starts the debounce. Client acceptance runs the complete current dataset through search, filter, facets, explicit sorting, and pagination, then resets or clamps page state. Server acceptance uses the ordinary request owner, including AbortSignal, monotonic stale-response rejection, retained rows, failure/retry, and atomic query/result publication. Search therefore round-trips through serialized state, URL adapters, saved views, exports, and selection-reset ownership without a second query channel. A native draft entered before hydration is adopted without replacing its input or retained result row.

The controller cannot interrupt synchronous CPU work already running. This is not performance qualification or a worker implementation. Calibrated 100k-row projection and ranked-search benchmarks remain a separate gate.
